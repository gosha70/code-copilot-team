# Origin record — one harness home (#411)

Recorded 2026-11-15 from the issue text and the repository at `56c2e5d`
(origin/master after PR #455). Quotations are the owner's words.

## Issue origin

Issue: https://github.com/gosha70/code-copilot-team/issues/411
(opened 2026-11-07 by the owner, label `enhancement`, no comments;
deferred from #410's planning comment of the same day).

> The harness has two home directories. `~/.cct/` holds the harness
> identity stamp (`harness.json`) and the Session Analytics configuration
> and store. `~/.code-copilot-team/` holds the Pi adapter's runtime home
> (`CCT_HOME`: runtime, resources, permissions, audit log), the reviewer
> profile (`providers.toml`), and is the per-project configuration
> convention (`.code-copilot-team/config.toml`).

> Decide the direction once and migrate as one change, not one file at a
> time.

Option A: "`~/.cct/` wins. Move `CCT_HOME` (Pi runtime home, reviewer
profile) and the per-project convention to `~/.cct/` and `.cct/`. Every
reader resolves through one helper per language (bash `scripts/lib`,
Python `scripts/lib/cct_config.py`, TypeScript
`adapters/pi/runtime/config/loader.ts`) with a fallback read of the
legacy path for one minor release, and `cct doctor` prints a one-line
notice while only the legacy path exists."

Option B: "`~/.code-copilot-team/` wins. Move `harness.json` and the
analytics store under it and retire `~/.cct/`."

> The naming goal (#410) points to A; the cost points to leaving the Pi
> home alone. Suggested timing: leave both as they are for the 2.0.x
> line and decide at 2.1.

Rejected alternatives in the issue: moving only `providers.toml`
("splits one home in two"); a symlink ("hides the split from the user
but not from `cct doctor`, the Pi init manifest hashes, or the tests
that spell the paths"). Risks named: "a missed reader silently falls
back and hides the move; the Pi init manifest records the config path
and hash." Compatibility: "a fallback read for one minor release;
`cct doctor` notice; CHANGELOG migration note."

## Repository facts (observed at 56c2e5d)

**Under `~/.cct/` today:** `harness.json` (written by
`adapters/claude-code/setup.sh`), `harness-stamps.jsonl` (the
`harness-stamp.sh` hook writes, Session Analytics reads; the path is
`CCT_HARNESS_STAMPS`, process environment only, since #448),
`session-analytics.json` (Session Analytics user config, `_USER_CONFIG`
in `config.py`, no override variable), the Kùzu graph store default
(`~/.cct/session-analytics-graph`), and the documented SQLite store
location (`~/.cct/sa.db` in the cookbook).

**Under `~/.code-copilot-team/` today:** `providers.toml` (read by
`peer-review`, `review-round-runner.sh`, `auto-build-loop.sh`,
`cooldown-supervisor.sh`, `provider-emit.sh`, `cct_config.py`,
`cct_doctor.py`, the `harness-stamp.sh` hook; override
`CCT_PROVIDER_PROFILE`, in one place `CCT_PROVIDERS_FILE`),
`routing.toml` (`CCT_ROUTING_REGISTRY`), `routing-state.json`
(`CCT_ROUTING_STATE`), `routing-probe-ledger.json`
(`CCT_ROUTING_PROBE_LEDGER`), the Pi home `CCT_HOME` with `pi/`
(runtime, resources, permissions, `audit.log`) and the Pi global
`config.toml` (`globalDir` in `loader.ts`; `index.ts` defaults
`CCT_HOME` to `~/.code-copilot-team`). The approved #400 spec (FR-1)
places `llms.toml`, the compatibility records and the session stamps
there too, "through one helper so #411 moves them together".

**Per project:** `.cct/` is the runtime-state directory (`review/`,
`auto-build/`, `memory.json`, `team.json`, `verify/`, `supervisor/`,
Pi session and workflow state; about 70 code sites), which projects
treat as untracked. `.code-copilot-team/config.toml` (plus
`config.local.toml` and the `.cct-init.json` manifest `pi-code init`
writes with the config path and hash) is the committed per-project Pi
configuration (3 code sites: `loader.ts`, `pi-code`, `provider-emit.sh`).

**Spellings:** 65 tracked files spell `.code-copilot-team` and 77 spell
`.cct` (CHANGELOG and specs excluded); the resolving code sites are the
ones listed above plus `scripts/setup.sh`'s help text, the
`providers.schema.json` description, `provider-profile-template.toml`,
`routing.toml.example`, the provider-emit golden fixtures,
`tests/test-pi-launcher.sh`, `tests/pi-runtime/config.test.mjs` and
`security-battery.test.mjs`, 9 doc pages, the README and the generated
configuration reference.

**Versions:** `v2.0.0` is the latest tag; `pi-code` and `package.json`
say 2.0.0; CHANGELOG `[Unreleased]` is the 2.1 line the issue named for
this decision.
