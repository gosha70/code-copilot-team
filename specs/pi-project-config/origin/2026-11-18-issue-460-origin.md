## Issue origin

Issue: https://github.com/gosha70/code-copilot-team/issues/460
(filed 2026-11-17 as the #411 D5 follow-up, no comments).

> #411 moves the user home to `~/.cct/`. A project's committed Pi
> configuration still lives in `.code-copilot-team/config.toml` (plus
> `config.local.toml` and the `.cct-init.json` manifest that
> `pi-code init` writes with the config path and hash), while the
> project's runtime state lives in `.cct/`. The two names differ again
> at the project level.

The issue proposed `.cct/config.toml` with a gitignore carve-out, one
resolver, a fallback for one minor release, a `pi-code doctor` notice,
no silent move, and `pi-code init` scaffolding the new path. It named
two things #411 did not settle: committed configuration inside the
untracked `.cct/` needs gitignore guidance, and the init manifest
records the config path and hash.

## Owner rulings, 2026-11-18

1. **Location.** Asked whether the committed configuration should be
   `.cct/config.toml` (with a gitignore carve-out) or `.cct.toml` at
   the repo root, the owner chose: ".cct.toml at the repo root".
2. **Gitignore.** "Not needed. The config is .cct.toml at the repo root.
   init only makes sure .cct/ is ignored, and doctor warns if git
   check-ignore .cct.toml says the config is ignored."
3. **Migration.** "Explicit command only" — the #411 rule: nothing
   moves silently.
4. **Fallback.** "Through 2.1.x, gone in 2.2", matching the user-home
   fallback so both legacy names disappear in the same release, with a
   condition: "If #460 misses the 2.1.0 release, the old location is
   read through the release after the one #460 ships in. Projects always
   get at least one full minor release to migrate, and the CHANGELOG
   states the removal version." (The last tag is `v2.0.0`; #411 sits in
   Unreleased, which will become 2.1.)
