# Specification: Copilot Reviewer Setup

**Feature ID**: `copilot-reviewer-setup`
**Input**: user directive 2026-07-30 (see plan.md `origin:`) with the full
AGENTS.md/CODE_REVIEW.md design supplied in the request.

## Summary

An abstracted installer that configures a copilot as the independent code
reviewer for a target project. Codex is the first supported tool: a short
"Code Review Rules" loader in the project's root `AGENTS.md` (the file Codex
loads automatically) directs review sessions to a committed
`docs/CODE_REVIEW.md` holding the full independent-review workflow, plus a
project-owned `docs/CODE_REVIEW_PROJECT.md` for repository-specific values.

## User Scenarios

- **US-1 New project**: a maintainer runs
  `./scripts/setup-reviewer.sh --codex <dir>` on a project with no
  `AGENTS.md`; the loader, managed review document, and project
  configuration are created; a fresh Codex session follows the rules on
  `/review`.
- **US-2 Existing instructions**: the project already has a hand-written
  `AGENTS.md`; setup appends only a marker-guarded block and never alters
  existing content; re-runs are byte-identical.
- **US-3 Customized configuration**: the maintainer fills in the
  `CODE_REVIEW_PROJECT.md` placeholders; later re-runs (refreshing the
  managed document) and uninstalls never destroy those values.
- **US-4 CCT-generated instructions**: the project's `AGENTS.md` is
  generated by `code-copilot-team`; setup never hand-edits it. If the
  generated file already carries the loader, setup succeeds; if it is a
  stale generation without the loader, setup fails loudly with the
  regeneration command — never a silent success with an inert setup.
- **US-5 Future copilots**: adding a tool is one installer/uninstaller
  function pair plus a dispatch-table entry; an unknown tool is rejected
  with the supported list.

## Requirements

- **FR-1** `scripts/setup-reviewer.sh` provides per-copilot dispatch
  (`--codex` first), `--uninstall`, `--list`, `--help`; unknown selection
  exits 64 naming the supported tools.
- **FR-2** Managed content (review document, loader block) is
  marker-identified, refreshable in place, and idempotent — a re-run on an
  unchanged tree is byte-identical.
- **FR-3** Project-owned content (`docs/CODE_REVIEW_PROJECT.md`) is
  created once from `shared/review/project-config-template.md` and never
  overwritten; uninstall removes it only while byte-identical to the
  template.
- **FR-4** Foreign files are never clobbered: a `docs/CODE_REVIEW.md` not
  carrying the managed marker is refused (exit 1) and left untouched.
- **FR-5** Generated instruction files are never hand-edited. With the
  loader present the install succeeds; without it the install exits 65 and
  names the regeneration command (`generate.sh` / adapter `setup.sh
  --sync`).
- **FR-6** `scripts/generate.sh` emits the loader block (same markers)
  into generated `adapters/codex/AGENTS.md`, within the 32 KiB cap, so
  regeneration preserves the rules.
- **FR-7** The review workflow document defines: independent-reviewer
  role, review-only boundary, source-of-truth order, CCT/SDD +
  origin-alignment gating, review procedure, AI-failure-mode checklist,
  finding standard, severity ladder (P0–P3), verdict rules
  (`PASS`/`FAIL`/`INCONCLUSIVE`), output format, and GitHub inline-comment
  rules — as supplied in the origin.
- **FR-8** Tests cover every FR above, including the destructive-path
  regressions (config survival across refresh/uninstall; stale-generated
  hard failure).

## Constraints

- **C-1** Review-only boundary: nothing installed may authorize the
  reviewing copilot to modify files, commit, push, or merge.
- **C-2** The installer must be safe to re-run at any time (idempotent,
  no data loss) — the failure mode "re-run destroys configuration" is a
  P1 defect class, found and fixed via independent review of PR #148.
- **C-3** Generated adapter output must stay within Codex's 32 KiB
  instruction cap; the full workflow document therefore lives outside
  `AGENTS.md`.
- **C-4** This feature is distinct from `code-reviewer-assistant` task 4.2
  (runner-native Codex peer review); see plan.md for the relationship.

## Definition of Done

- Installer + shared sources + generator block merged with all FR-mapped
  tests green in CI.
- Independent review findings on PR #148 remediated with regression tests.
- README documents the feature (setup command, file layout, ownership
  model).
