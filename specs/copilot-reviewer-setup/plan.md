# Implementation Plan: Copilot Reviewer Setup

**Branch flow**: delivered via PR #148 (initial) + follow-up PR addressing
the independent Codex review findings on #148.
**Input**: specs/copilot-reviewer-setup/spec.md

## Approach

- Source of truth in `shared/review/`: the full review workflow
  (`CODE_REVIEW.md`), the short loader section (`reviewer-loader.md`), and
  the project-owned configuration template
  (`project-config-template.md`).
- `scripts/setup-reviewer.sh`: per-copilot dispatch table (`--codex` now;
  one `install_<tool>()`/`uninstall_<tool>()` pair per future tool).
  Managed content is marker-guarded and refreshable; project-owned content
  is created once and never overwritten or deleted after customization.
- Generator layer: `scripts/generate.sh` emits the same marker-guarded
  loader block into generated `adapters/codex/AGENTS.md`, inside the
  32 KiB Codex size cap, so regeneration preserves the rules.
- Tests: `tests/test-setup-reviewer.sh` (idempotency, ownership,
  refusal/failure paths, generator integration).

## Relationship to code-reviewer-assistant Phase 4.2

`specs/code-reviewer-assistant/tasks.md` task 4.2 ("Codex adapter native
peer-review support") specifies the *runner-native* path:
`review-round-runner.sh`, snapshot isolation, `.cct/review/` artifacts,
circuit breakers. This feature is a *distinct, complementary* mode: a
manually started, instruction-file-driven independent review session
(local `/review`, `codex review`, or GitHub `@codex review`). It does not
implement, replace, or partially deliver 4.2; 4.2 remains open with its
own contract. The two share the review-only, fail-closed philosophy but
neither depends on the other.

## Pull-request decomposition

- PR #148 — initial delivery (shared docs, installer, generator block,
  29-assertion suite).
- Follow-up PR — independent-review remediation: project-owned
  configuration split (refresh/uninstall can no longer destroy it), stale
