## The two criteria that are not a plain "met"

### C13 — requested and effective model identities recorded → MET AS DESIGNED

Re-derived from source rather than inherited.

`rt_effective_model` (`cooldown-supervisor.sh:669`) extracts a served
model from the transcript when one is reported. For codex it is always
null, and that is correct: **no codex event reports a served model.**
The `model` field in codex's `backend_metadata`
(`backends/codex.py:253`) is the string the harness *passed* via
`--model` — and it may be empty, in which case codex silently uses its
`config.toml` default and the harness never learns what ran. Recording
that as `effective_model` would assert an equality nobody verified.

The design records the *state* of the effective identity rather than
guessing a value:

- schema: `effective_model` is "null when it cannot be verified —
  NEVER silently assumed equal to `requested_model`";
- the supervisor journals `effective model UNVERIFIED (no transcript
  identity) — recorded null, never assumed`;
- when a transcript *does* report a differing model, the run refuses
  with `routing_model_identity_mismatch` rather than rerouting.

The criterion says identities are *recorded*. An explicit, journaled
UNVERIFIED is a recording; a fabricated equality would not be. Met as
designed.

### C30 — tokens, costs, failed verifiers, repair cycles, endpoint, model → PARTIAL, BLOCKS CLOSURE

Four of the six are recorded on the routed path:

| Component | Evidence |
|---|---|
| failed verifier commands | `EVAL_FAILING` plus the failures file and log (`cooldown-supervisor.sh:1079-1093`) |
| repair cycles | `rounds` in `packet-outcome.json` and the provisional record (`:1159`, `:1167`) |
| effective endpoint | `endpoint_ref` resolved and journaled (`:486`) |
| effective model | the C13 tri-state above |

**Tokens and costs are not recorded on the routed path, and the
criterion is therefore not met.** The normalized routing result at
`95c9fbe` carries backend, provider, profile, requested/effective
model, endpoint, failure evidence, the context-limit group and
artifacts — and **no token or cost field at all**. There is no usage
or accounting contract on a routed attempt to be accurate or
inaccurate.

Two things that look like coverage but are not, and are explicitly
**not** counted here:

- **The benchmark-runner codex backend parses `input_tokens`,
  `output_tokens` and cached tokens from its JSONL transcript.** That
  proves the numbers are *obtainable*; it is not evidence that a
  runtime routed attempt durably captures or joins them. Different
  code path, different artifact.
- **Session-analytics computes cost at ingest** from token counts plus
  a configured pricing table, correctly yielding NULL for an unknown
  or unpriced model, and the driver debits `.totals.cost_usd` /
  `.totals.cost_estimated_usd` against its caps. The accounting
  semantics are sound, but they only serve C30 once a *particular
  routed attempt* is durably connected to its own token evidence.
  Counting a cost cap as usage recording would be satisfying the
  criterion by implication, which is exactly what this audit exists to
  refuse.

Codex is documented as reporting token usage but no USD, with the
adapter debiting the unmetered estimate path — so even where tokens
exist upstream, no routed record joins them.

The fix is small and is tracked as its own increment; see below.

## Recommendation — #109 stays OPEN

Close only after C30 is genuinely satisfied. The remaining work is one
small increment, **#109-G: routed usage/cost evidence**, and nothing
else. It is deliberately not a routing-policy feature.

### The contract G must add

Every newly produced routed attempt carries a normalized
usage/accounting block:

```text
tokens:
  input | output | cache_read | cache_write
  status: reported | unavailable
cost:
  usd
  basis: reported | computed | unpriced | unavailable
  price_version
```

**The governing rule is that unknown stays unknown.** No token count is
invented and no USD is claimed merely because a cost cap or an estimate
exists. Concretely:

| Situation | Record |
|---|---|
| backend exposes tokens (codex) | capture from the authoritative result/transcript |
| backend exposes no accounting | `null` + `status=unavailable` — persisted, never silently omitted |
| tokens known + pricing configured | computed cost, with pricing provenance and version |
| model known, no price | `cost_usd=null`, `basis=unpriced` — matching existing analytics semantics |
| subscription execution, no per-request marginal cost | explicit `unavailable`, never a fabricated API-style figure |

An explicit, durable `unavailable`/`unpriced` **is** accurate recording
when the backend genuinely cannot expose the quantity. What fails C30
is today's state: no accounting contract on the routed record at all.

### The acceptance discriminator

Field presence is not the test. A routed-attempt fixture with known
usage must prove:

```text
backend reports input=120, output=30, cache_read=50
  -> the durable routing result carries exactly those values
  -> bound to that attempt / profile / effective identity

pricing configured   -> cost recomputed from those values,
                        price version + provenance present
pricing absent       -> cost NULL / unpriced, never 0
usage unavailable    -> tokens NULL + status unavailable,
                        never inferred from budget or cost-cap values
```

Then mutate away the usage propagation and the pricing provenance and
confirm the named C30 test fails for that reason.
