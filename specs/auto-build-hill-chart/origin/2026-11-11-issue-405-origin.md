# Origin record — auto-build moves the pitch's hill-chart scopes (#405)

Recorded 2026-11-11 from the issue text and the repository at `a63bf6d`
(origin/master after PR #444). Quotations are the owner's words.

## Issue origin

Issue: https://github.com/gosha70/code-copilot-team/issues/405
(opened 2026-11-04 by the owner, label `enhancement`, no comments).

> An auto-build run never moves the active pitch's hill-chart scopes,
> so every driver-built cycle reaches `/cooldown` with all scopes
> `uphill`.

Evidence the issue cites: `scripts/auto-build-loop.sh` has no reference
to `hill`; wiki-studio cycles 03 and 04 closed with every scope `uphill`
in `hill.json` and were set to `done` by hand.

The two suggested resolutions:

> Either map each `## US<n>:` phase to a scope in `automation.json`
> (or read the mapping from the pitch) and set the scope `done` when
> its phase lands, or have `/cooldown` state that driver-built cycles
> set all scopes at close and record that in the bet log.

## Repository facts (observed at a63bf6d)

- `scripts/auto-build-loop.sh` (6,248 lines): `SPEC_DIR` is
  `$PROJECT_DIR/specs/$FEATURE_ID` with no pitch fallback; phases come
  from `enumerate_phases`, which reads `## US<n>:` headings in
  `tasks.md` (or the `phases.phases` override); `phase_gate` runs the
  origin re-check and commits the review artifact with `driver_commit`
  scoped to `$SPEC_DIR`; the phase is marked `done` in the ledger only
  after `coverage_gate` passes; the run ends with the automation
  summary artifact commit and `set_status "done"`. `driver_commit`
  with paths stages only those paths; without paths it stages
  everything (`git add -A`) for build commits. Nothing in the driver
  reads or writes `hill.json`.
- `scripts/validate-spec.sh` and `scripts/check-origin-alignment.sh`
  both resolve a bare feature id as `specs/<id>` and fall back to
  `specs/pitches/<id>`.
- `shared/templates/sdd/hill-chart.json`: scopes `S<n>` with status
  `uphill | downhill | done`, `last_updated`, optional `note`, root
  `updated_at`; "done: scope complete and verified".
- `/cycle-start` writes `hill.json` with every scope `uphill` and
  refuses to overwrite one; `/hill <scope> <up|down|done>` is the
  manual transition with its allowed-transition table; `/cooldown`
  reads `hill.json` to suggest `shipped` (all done), partial, or
  `shelved` (none done), then asks the user.
- The `scope-executor` agent moves a scope `uphill → downhill` when it
  starts execution and states: "Marking `done` is a human-driven
  `/hill` call, not yours. This preserves the verification gate."
- The dogfood pitch `specs/pitches/0001-shape-up-support/tasks.md`
  names scopes in its phase headings (`## US1 + US7 (S1): …`), which
  `enumerate_phases`'s `^## US[0-9]+:` pattern does not match; the
  convention of carrying `(S<n>)` in the heading already exists.
- PR #440's description claims hill-chart automation for #405, but its
  files are the #389 spec bundle only; no implementation exists on any
  branch.
