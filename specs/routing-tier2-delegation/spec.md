# Spec: Tier-2 delegation + reconciliation — increment C of #109

Increment B answered availability ("the preferred path cannot
continue, so move safely"). Increment C answers COST AND CAPABILITY:
send explicitly bounded work to a cheaper or local Tier-2 model BY
POLICY — even while every Tier-1 profile is healthy — and make its
work authoritative only through Tier-1 reconciliation. The
architectural rule is load-bearing everywhere: **Tier-2 is delegated
bounded work, never another unrestricted failover target.** A Tier-2
model never receives an open-ended run, never self-reports success,
and never lands anything without a Tier-1 gatekeeper.

## User Scenarios

- An operator marks a handful of mechanical tasks (`tier2_preferred`)
  in a feature's routing-task metadata. The supervised run delegates
  exactly those tasks to the local Qwen profile as bounded packets —
  each in a fresh session with a minimal tool profile and an exact
  file allowlist — while architecture-touching tasks continue on
  Sonnet. Anthropic tokens are spent on judgment, not typing.
- Every Tier-1 pool is exhausted mid-run. Tasks marked
  `tier2_fallback` with complete dependencies continue on the local
  profile; Tier-1-only tasks stay queued; nothing the local model
  produced lands until a recovered Tier-1 profile reconciles it.
- A local task passes its tests but rewrote a forbidden file. It
  never becomes `verified_provisional`; the packet fails with the
  named boundary violation.
- An operator asks `cct routing explain --feature F --task T` and
  sees the task's route class, its safety-floor evaluation, and the
  same candidate table increment A ships for route classes.

## Requirements

- **FR-C1 (task route metadata).** A per-feature artifact
  `specs/<feature>/routing-tasks.yaml` (constrained layout, like
  verification.yaml; schema + executable validator) declares per-task:
  stable id, route class (`primary_only|tier1_only|tier2_fallback|
  tier2_preferred`), exact outcome, allowed files, FR references
  (bound to verification.yaml), dependencies, forbidden-change
  categories, reorderable flag. A task without metadata defaults to
  `tier1_only`. The artifact can NARROW safety, never widen it.
- **FR-C2 (the safety floor).** Tasks touching architecture,
  authentication/authorization, cryptography, security policy,
  database migrations, dependency manifests, public API surfaces, CI/
  verification tooling, or the routing/verification artifacts
  themselves are FORCED to Tier-1 regardless of annotation — enforced
  structurally (path- and category-based, validated at metadata
  admission AND re-checked at packet build). An unsafe annotation is
  a named refusal, not a silent downgrade.
- **FR-C3 (packet generation).** A durable, backend-neutral,
  IMMUTABLE packet per delegated task (versioned closed envelope,
  sibling of B's result envelope): packet id + digest, task identity
  + outcome, allowed files, forbidden categories, FR refs with their
  verification.yaml verifier commands, base commit + current diff
  sha, source-artifact provenance digests, prior evidence refs.
  Packets are generated by the driver-side tooling from FROZEN
  artifacts, never by the Tier-2 model; execution and reconciliation
  bind to the packet at point of use (digest + provenance verified;
  drift is a named refusal, never a silent rebuild or downgrade).
- **FR-C4 (bounded execution).** One packet = one FRESH Tier-2
  session under the profile's minimal tool profile, launched by the
  same supervisor machinery as B (same env wiring, secret scrubbing,
  crash ordering, attempt idempotency). The packet prompt carries the
  packet only. File-scope enforcement is DRIVER-OWNED, post-hoc
  verifiable, and CUMULATIVE against the packet's base commit after
  EVERY modifying phase (initial build, each repair round, and
  reconciliation changes): the worktree diff must touch ONLY allowed
  files — any excursion (including verifier/test files, which are
  always protected) fails the phase with the named violation.
- **FR-C5 (driver-owned verification + bounded repair).** Success is
  decided ONLY by re-running the packet's verifier commands (from
  verification.yaml) plus the scope check — never by the model's
  self-report. A failing packet gets a bounded repair loop
  (`RC_MAX_REPAIR_ROUNDS`, default 2, implementation default not
  compatibility surface) with THRASH DETECTION: a repeated failure
  signature, a whole-file rewrite of an allowed file, or no reduction
  in failing verifiers ends the loop early with a named reason.
  Diff-scope budgets (changed-line ceiling per packet, named default)
  refuse runaway rewrites.
- **FR-C6 (verified_provisional).** A packet that passes scope +
  verifiers enters `verified_provisional` — recorded in the routing
  ledger with full evidence (diff sha, verifier outputs, repair
  count). Provisional work may be committed as WIP by the DRIVER
  (which retains sole git ownership) but can never satisfy a phase or
  landing gate, and the driver's gates treat provisional tasks as
  incomplete until reconciled.
- **FR-C7 (Tier-1 reconciliation).** A Tier-1 profile holding the
  `reconcile` role reviews each provisional packet in a FRESH
  session: the patch, the packet, and the verifier evidence. It may
  simplify or repair, then the driver re-runs the packet verifiers,
  and the outcome is recorded as `accepted | accepted_with_changes |
  rejected` (rejected reverts the packet's diff). Only accepted work
  counts toward completion. Reconciler edits obey the SAME packet
  scope and protections as the builder's. Reconciliation requires
  POSITIVELY established reviewer independence (B's evaluator, a
  stronger C disposition): `not_independent` AND `unevaluable` both
  fail closed with their own named reasons — promotion never happens
  when independence cannot be established. Reconciliation is
  cost-accounted like any attempt.
- **FR-C8 (selection legality).** Tier-2 profiles become selectable
  ONLY for a bounded packet whose route class permits them
  (`tier2_fallback` when Tier-1 is PERMANENTLY exhausted per B's
  authoritative selector output — temporary exhaustion waits, never
  unlocks; `tier2_preferred` by policy) and whose dependencies, file
  scope, and verifier resolution are complete. Terminal outcomes
  from an actual Tier-1 attempt remain terminal and never become a
  fallback opportunity. B's whole-run selection stays tier1-only. If
  no independent Tier-2-safe work exists when Tier-1 is exhausted,
  the run parks per B's semantics — the tier requirement is never
  weakened.
- **FR-C9 (task-addressed explain).** `cct routing explain --feature
  <id> --task <task-id>` resolves the task's route class and safety
  floor from routing-tasks.yaml and renders increment A's candidate
  table for it (still pure configuration resolution — the recorded
  deviation from A closes).
- **FR-C10 (accounting + audit).** Every Tier-2 packet attempt and
  every reconciliation attempt rides the existing cost/cap machinery
  and the routing journal (packet id, profile, verdicts, repair
  rounds, reconciliation outcome, rework ratio inputs).

## Constraints

- Tier-2 work is packet-scoped by construction: no code path hands a
  Tier-2 profile an unbounded run (the supervisor's whole-run mode
  remains tier1-only).
- The safety floor is structural and cannot be annotated away;
  metadata admission and packet build BOTH enforce it.
- No phase/landing PASS from Tier-2 self-report; verifier commands
  and test files are write-protected from the packet's file scope.
- B's frozen contracts are consumed unchanged (result envelope,
  crash ordering, state store, selection oracle, independence gate);
  where C extends an enum or envelope it does so visibly with its
  own version/regressions.
- Numeric budgets (repair rounds, changed-line ceilings) are named
  implementation defaults, journaled when applied — not
  configuration or compatibility surface in C.
- Routing remains opt-in end to end; absent metadata means tier1_only
  for every task; bash 3.2; no new runtime dependency.

## Success criteria

- **SC-C1** The metadata artifact validates (closed shape; unknown
  route class, dangling FR ref, unknown dependency, and an
  allowed-file entry escaping the project root are named refusals);
  a task without metadata resolves tier1_only.
- **SC-C2** Safety floor: a `tier2_preferred` annotation on a task
  whose allowed files include a dependency manifest (and each other
  floor category) is refused BY NAME at admission; a packet-build
  re-check refuses a floor violation introduced after admission.
- **SC-C3** Packet generation is deterministic and complete: the
  envelope carries the verifier commands from verification.yaml
  verbatim, the exact allowlist, the base identity, and the
  provenance digests; regenerating from unchanged inputs is
  byte-identical; a tampered envelope (digest mismatch) and a
  drifted source artifact at point of use are each refused BY NAME —
  never silently rebuilt.
- **SC-C4** A packet session that touches a file outside its
  allowlist — or any verifier/test file — fails with the named scope
  violation even when all verifiers pass; the diff is reverted.
- **SC-C5** Verifier-decided success: a packet whose model reports
  success but whose verifiers fail is a failed packet; repair rounds
  are bounded; each thrash signature (repeated failure, whole-file
  rewrite, no-reduction) ends the loop early with its own named
  reason; the changed-line budget is cumulative from the packet base
  (two in-budget rounds cannot double the effective scope) and
  refuses a runaway diff; every repair round is a fresh supervised
  attempt with its own attempt id under B's crash ordering.
- **SC-C6** A passing packet lands in `verified_provisional` with
  full evidence and does NOT satisfy the driver's completion
  accounting; the run ends parked/incomplete if reconciliation never
  happens.
- **SC-C7** Reconciliation: accepted, accepted_with_changes (the
  Tier-1 edit re-verified, and refused when it escapes the packet
  scope), and rejected (diff reverted) all proven; a colliding
  reconciler is refused by name; an UNEVALUABLE independence
  evaluation is refused by its own name — promotion is impossible
  without positively established independence.
- **SC-C8** Selection legality: tier2_preferred delegates while
  Tier-1 is healthy; tier2_fallback delegates ONLY on B's
  permanent-exhaustion selector shape (temporary exhaustion provably
  waits and re-selects); a terminal Tier-1 attempt outcome never
  unlocks Tier-2; a tier1_only task never reaches a Tier-2 profile
  even when it is the only candidate; exhausted-Tier-1 with no
  Tier-2-safe work parks per B.
- **SC-C9** Task-addressed explain renders the route class, the
  safety-floor evaluation, and the candidate table; it remains pure
  (network shim + state byte-identity, as in A).
- **SC-C10** Docs/CHANGELOG/pins land with the behavior; the full
  sweep stays green modulo the known host baseline; every SC above
  is mutation-verified in isolated worktrees.

## Non-goals (deferred per the umbrella)

Probes/failback/`routing tick` (D); benchmarks, routing-quality
metrics, learned routing (E); the codex execution adapter (own child
increment); multi-round visual loops; any change to reviewer
providers.toml semantics; automatic route-class inference (regex/LLM
classifiers may PROPOSE in a later increment but never silently
downgrade below the declared floor).
