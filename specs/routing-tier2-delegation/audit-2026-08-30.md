# Acceptance audit — #254 (increment C of #109)

- **Date:** 2026-08-30
- **Audited at:** `master` @ `bc32a1e` (tree clean)
- **Issue:** #254 — Tier-2 delegation + reconciliation
- **Method:** each Scope bullet of the issue body probed against the
  code; the six routing suites executed.
- **Verdict:** every scope bullet **met**. No findings against #254's
  own scope. Nothing blocks closing it.

#254 ships no acceptance-criteria checklist. Its `Scope` bullets are
treated as the criteria, numbered C1–C8 for reference.

## Per-bullet findings

### C1 — task route metadata, closed route classes, structural safety floor — MET

`scripts/lib/routing-tasks.sh` implements the constrained dialect for
`specs/<feature>/routing-tasks.yaml`. Route classes are the closed set
`primary_only|tier1_only|tier2_fallback|tier2_preferred`, validated at
`routing-select.sh:67-73` — an out-of-vocabulary class is refused by
name, never coerced. Absent metadata resolving to `tier1_only` is
confirmed by `routing-cli.sh`'s own usage text ("absence is valid and
resolves tier1_only"), verified by running the binary.

The structural safety floor is nine closed categories with one named
pattern set each (`routing-tasks.sh:49-54`). The direction of authority
required by the bullet is enforced explicitly: *"Metadata can NARROW
safety, never widen it"* (`:27`) and *"FLOOR PROTECTION OUTRANKS THE
ANNOTATION"* (`:132`). The routing shell itself is inside the floor
(`:112` — `routing-tasks.yaml`, `routing.toml`, `routing-state.json`,
`routing-cli.sh`, `cooldown-supervisor.sh`, `routing-*.sh`,
`routing-*.json`), so a delegated Tier-2 task cannot edit the machinery
that governs it.

Enforcement at both points the bullet names — admission and packet
build — is present; `test-routing-tasks.sh` covers this suite at 154
assertions.

### C2 — immutable provenance-bound packets — MET

`scripts/lib/routing-packet.sh` defines the versioned closed envelope.
`packet_digest` is sha256 over the canonical envelope bytes *minus the
digest field itself* (`jq -S -c`, no trailing newline) so semantically
identical envelopes share a digest (`:13-16`); `packet_id` is
`<feature>:<task>:<digest:0:12>` (`:17`), and every durable reference
carries both id and digest (`:19`).

The two refusals the bullet requires are named enum members, not
free text: `packet_provenance_drift` and `packet_id_reuse` are in
`RP_PACKET_REASONS` (`:46`). A file already claiming the candidate id
with a different digest is refused as tamper evidence, *"never an
overwrite"* (`:20-21`). Point-of-use validation is staged
(`:28-29` — digest verification inside `rp_validate`, then
`rp_provenance_check` comparing live artifacts against recorded
digests), so drift refuses rather than silently rebuilding.

### C3 — bounded execution via `--delegate` — MET

`cooldown-supervisor.sh:111-112` parses `--delegate <task-id>` (and the
`=` form). The routing opt-in is a named refusal, not an implication:
*"--delegate requires --routing: packet delegation is part of the
routing opt-in (#254), never implied"* (`:138`). `--delegate` and
`--reconcile` are mutually exclusive — *"one bounded lifecycle per
run"* (`:146`) — and `--packet` is refused outside `--delegate`
(`:150`). The header at `:38` documents the "exactly ONE bounded"
contract.

### C4 — driver-owned quality gates — MET

Bounded repair: `RC_MAX_REPAIR_ROUNDS=2` (`cooldown-supervisor.sh:854`)
with the terminal refusal `packet_verifiers_unsatisfied` when verifiers
still fail after the initial round plus the repair budget (`:1097-1098`).

The bullet requires **three named thrash signatures**. Exactly three
exist, each with its own refusal:

| Signature | Site | Meaning |
|---|---|---|
| `packet_thrash_repeated_failure` | `:1085` | round reproduces a prior round's normalized failure signature — explicitly subsumes A/B/A oscillation |
| `packet_thrash_rewrite` | `:1088` | whole-file-rewrite threshold (`RC_REWRITE_FRACTION_PCT=80`, `:855`) |
| `packet_thrash_no_reduction` | `:1092` | failing verifier count did not fall versus the previous round |

`packet_scope_violation` and `packet_budget_exceeded` (`routing-packet.sh:46`)
carry the cumulative scope-before-verifiers and changed-line-budget
gates the bullet names.

### C5 — `verified_provisional` — MET

Written to the driver ledger with full evidence at
`cooldown-supervisor.sh:1069-1074`. That it satisfies no phase or
landing gate is enforced structurally rather than asserted in prose:
`:1429` names reconciliation as *"THE promotion boundary"*, `:1433-1438`
counts outstanding `verified_provisional` records as `provisional_pending`,
and `:1510` refuses reconciliation when no such record exists for the
task.

### C6 — Tier-1 reconciliation with fail-closed independence — MET

`--reconcile <task-id>` parsed at `cooldown-supervisor.sh:117-118`,
gated on `--routing` by the same named-refusal discipline as
`--delegate` (`:142`).

Independence must be **positively** established, and both non-positive
outcomes refuse promotion — the enum carries `reconcile_not_independent`
*and* `reconcile_independence_unevaluable` as distinct members
(`routing-packet.sh:46`), so "could not evaluate" can never be read as
"independent". `reconcile_verdict_missing` closes the third hole. The
independence evaluator's own refusal path is at
`cooldown-supervisor.sh:598-601`, which journals the collision and
refuses with `routing_reviewer_not_independent` rather than
downgrading: *"independence is never downgraded to keep moving"*.

### C7 — selection legality — MET

`rt_select` is route-class-aware (`routing-select.sh:65-66`, optional
4th argument). The bullet's compatibility gate — *absent argument → B
byte-identical* — is pinned by an actual assertion, not by inspection:
`test-routing-delegation.sh:150`, *"tier1_only output is byte-identical
to the absent argument"*, with the intent documented at `:4`.

The `tier2_fallback` unlock is pinned to B's **permanent-exhaustion
selector shape** exactly as the bullet requires: tier2 is evaluated
only when the tier1 pass ended with no selection **and** no
`earliest_retry` (`routing-select.sh:194`). A temporary exhaustion
waits — *"the tier requirement is never weakened"* (`:203`). The
comment at `:59-64` records that terminal Tier-1 attempt outcomes
(denied / unknown / identity / independence / crash) are handled above
this oracle by the action table and never re-enter selection as a
fallback opportunity — which is the bullet's "terminal Tier-1 attempt
outcomes never unlock Tier-2".

One shared candidate evaluator (`_rt_eval`, `:87`) serves every route
class, so filter semantics cannot drift between B's path and C's; only
membership and tier precedence differ. Within a tier the total order
(priority ASC → id lexical ASC) is untouched by route class.

### C8 — task-addressed explain + tier2 repo-key promotion — MET

`explain --feature <id> --task <id>` is implemented
(`routing-cli.sh:87-88`) and covered by nine assertions at
`test-routing-tasks.sh:767-808`, including both half-specified forms
refused with exit 2 (`--feature` without `--task`, `--task` without
`--feature`), `--task` refused on `validate`, the successful
`--feature X --task Y` path, and an unknown task id. This closes
increment A's recorded deviation.

The `tier2` repo-key promotion is restriction-only and shared: a single
reader, `rc_tier2_allowed` (`routing-config.sh:625-632`), backs **both**
the CLI's task-addressed explain and the supervisor's `--delegate`
refusal, explicitly *"so the two surfaces can never drift"*. It carries
the explicit-null discipline so an operator's `false` cannot be widened
back to `true`. Defense in depth is present at the selector too
(`routing-select.sh:188-193`, `:213-218`), which rejects the whole
tier2 pass when repository policy forbids delegation.

## Recommendation

**#254 is closable on its own scope.** All eight scope bullets are met,
the architectural rule the issue calls load-bearing — *Tier-2 is
delegated bounded work, never another unrestricted failover target* —
is enforced structurally at four independent points (route-class
vocabulary, safety floor, permanent-exhaustion unlock, reconciliation
promotion boundary) rather than by convention, and both non-positive
independence outcomes refuse promotion.

Closing #254 leaves #109 open (umbrella).
